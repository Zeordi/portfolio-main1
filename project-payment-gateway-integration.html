API & Backend Role: Backend Engineer Tech: Python, FastAPI, Docker, PostgreSQL, Stripe, PayPal, webhooks

Payment Gateway Integration

A secure payment-processing backend with multi-provider support and idempotent webhook handling.

Python FastAPI Docker PostgreSQL Stripe PayPal webhooks

I built a FastAPI service that tokenizes card data client-side (via Stripe Elements) so raw PAN never hits our backend, routes each payment to the correct provider, and stores only a provider-agnostic transaction record in PostgreSQL. Webhooks are verified by signature and made idempotent with a deterministic event-id key so duplicate deliveries never double-charge a customer.

Provider Abstraction

A small provider interface in FastAPI normalizes checkout, capture, refund and void operations across Stripe, Chapa (Ethiopian card rail) and PayPal. Adding a new provider is a single class implementing the interface.

Webhook Safety & Idempotency

Incoming webhooks are signature-verified and de-duplicated by provider event id before any state change. Payments are never mutated twice; the audit trail is append-only in PostgreSQL with a strict unique constraint on the external event id.

PCI Scope

No card data is ever received by our servers: browsers tokenize via the providers' JS SDKs and we store only the resulting token and a masked brand/last4 reference for the user's receipt history.

Challenge

We needed a single checkout experience that supported multiple payment providers (credit cards, mobile money and bank rails) while keeping PCI-sensitive data off our servers and surviving webhook redelivery and retries safely.

Outcome

Checkout success rate improved to ~98% after provider fallback was added, and the idempotent webhook handler has processed hundreds of thousands of events with zero duplicate charges. The service runs in Docker on a small autoscaled pool behind an internal load balancer.
